CAPA: Routes

Responsabilidad:
La capa de Routes actúa como la interfaz HTTP del backend. Aquí se definen los endpoints REST con Crow, se reciben y validan las peticiones JSON y se responden con estructuras serializadas en JSON. Esta capa no debe contener lógica compleja de negocio ni consultas directas a la base de datos.

Qué tipo de archivos van aquí:
- controladores HTTP o handlers por recurso
- DTOs o ViewModels de entrada/salida
- validaciones ligeras de esquema y errores HTTP
- serialización/deserialización con nlohmann::json
- archivos de definición de rutas por entidad o dominio

Buenas prácticas de diseño:
- Mantener cada ruta enfocada en un recurso o caso de uso específico.
- Delegar la lógica del negocio a Services.
- Conservar respuestas consistentes: código HTTP, mensajes y payload JSON.
- Evitar lógica de acceso a datos dentro de esta capa.
- Hacer un manejo centralizado de errores para no duplicar validaciones.
- Usar nombres claros y coherentes con la API REST (/api/... o /health).
